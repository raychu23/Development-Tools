# Human study kit: does a visual/learning tool help a beginner

Use when the claim is about people ("a beginner answers faster/more correctly with the panel") and no participants are on hand yet. The agent's job is to make the study runnable by someone else and scoreable with one command; it never substitutes simulated beginners as evidence (a model cannot tell whether a picture helps a human, and agent behaviour is measured separately in agent-tool-ab.md).

## Kit contents (one folder, all committed)
- README protocol a non-author can run: who to recruit, setup commands, arm definitions, order table, script to read aloud, what to record, how to score, "what this can and cannot show".
- `tasks.json` (prompts only) and `keys.json` (experimenter only), both generated by a script from the keyed ticket file so they reproduce; participants never see the keys.
- `score.mjs`: per-arm mean F1, median seconds, exact rate, paired difference per person, and a caution that says how many people have BOTH arms. A scorer test plus a clearly named synthetic file (`SYNTHETIC-NOT-REAL-DATA.json`) prove it works.

## Design rules
- Crossover: each person does both arms, order and task set counterbalanced; the table is balanced only for its own size (4 people, or multiples), so tell the user to recruit exactly that and not to add a fifth.
- Transfer probe (a short no-tool question after each block) must use functions that NO set task touches, and its difficulty only cancels when pooled over the full design: say "never read one person's transfer difference". Calling it a learning study overclaims; it is a probe.
- Task sets that are not type-matched are acceptable only if the counterbalancing carries them; say so.
- Make the study copy match the prompts: if a prompt says "production files" or the keys exclude tests, delete test files from the copy, because the tool under test will list them and a literal answer scores below 1.
- Keep tool state out of the participant's file tree (state-dir env var) and state how the no-tool window is opened without the extension (close the tool window first; an editor reuses an already-open window for the same folder).
- Time budget = sum of per-task limits + practice + debrief, not the typical run.

## Review checks (have a fresh reviewer do them)
- Follow the README from a clean clone into a scratch dir; launch the real tool; report ambiguous steps.
- Hand-verify three keys of different types against the repo; confirm `tasks.json` holds no keys; rebuild from the generator and diff.
- Attack the scorer: duplicates, empty/null answers, `./` prefixes, a path answer with right endpoints and a fake edge, unknown arm, missing key, missing/null seconds, a person with one arm. Make bad rows stop with the row named instead of being dropped or double-counted.
- Check the order table for confounds (a transfer task always following the same set).
